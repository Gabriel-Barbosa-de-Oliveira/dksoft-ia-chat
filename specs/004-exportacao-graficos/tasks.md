# Tasks: Exportação de Arquivos e Gráficos no Chat

**Input**: documentos de design em `specs/004-exportacao-graficos/`

**Pré-requisitos**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/http-exports.md](./contracts/http-exports.md), [contracts/sse-events.md](./contracts/sse-events.md), [contracts/agent-tools.md](./contracts/agent-tools.md), [contracts/ui.md](./contracts/ui.md), [quickstart.md](./quickstart.md)

**Testes**: obrigatórios. A constitution (princípio V) exige teste para toda lógica nova, então cada tarefa de implementação inclui o arquivo `*.test.ts`/`*.test.tsx` ao lado do código. Testes de unidade **nunca usam rede**: modelo, MCP, API DKSOFT, `fetch`, relógio e identificadores são fakes injetados. Os geradores de arquivo são testados **reabrindo** o arquivo produzido.

**Organização**: por história de usuário, para cada uma ser implementada e validada sozinha depois da fase de fundação.

## Formato: `[ID] [P?] [Story] Descrição com caminho`

- **[P]**: pode rodar em paralelo (arquivos diferentes, sem dependência de tarefa incompleta)
- **[USn]**: história da spec a que a tarefa pertence (só nas fases de história)
- Caminhos relativos à raiz do repositório. Testes ao lado do código; E2E do front em `web/e2e/`
- Comandos: `npm --prefix api run typecheck` · `npm --prefix api test` · `npm --prefix web run typecheck` · `lint` · `test` · `test:e2e`
- Cada tarefa cabe em um commit (princípio VIII); `typecheck`, `lint` e `test` do(s) pacote(s) tocado(s) verdes antes de cada commit
- **Convenções de código** (constitution + [plan.md](./plan.md)):
  - `api/`: 4 espaços, sem ponto e vírgula, imports locais com extensão `.ts`. `domain/` é **puro**: sem IO, `Date.now()`, `Math.random()` nem `randomUUID()` (relógio e ids entram por parâmetro). IO e CPU pesada só em `services/`, `store/` e `render/`; `http/` só traduz HTTP; erros de domínio são classes traduzidas na borda (`http/errors.ts`) ou, para o modelo, em texto da tool
  - `web/`: 2 espaços, ponto e vírgula. `src/lib/` é puro (sem React, `fetch`, DOM, `import.meta.env` nem `Date.now()`); IO só em `src/api/` e `src/storage/`; `hooks/` liga IO ao reducer; `components/` são finos. CSS por módulo com `var(--…)`, sem hex, `px` ou `font-family` literais fora de `modernist.css` e `app-tokens.css`
  - Entrada externa validada com zod; os contratos de `api/` e `web/` são **espelhados à mão** (copiar casos de teste, nunca importar entre pacotes)
  - Tudo que é novo no backend fica atrás de `artifactsEnabled`; com a chave desligada o comportamento é o do MVP
  - Textos para a pessoa em pt-BR, exatamente como em [contracts/ui.md](./contracts/ui.md) e [contracts/agent-tools.md](./contracts/agent-tools.md)
  - Nunca ler nem commitar `.env`; nenhum segredo, chave de acesso, nome de arquivo ou `fileId` em log, URL ou mensagem de erro

```text
                         └─► US2 ──┘         ├─► US5 (US1 + US3)

```

1. Domínio puro e testes ([P]) → 2. armazéns e adaptadores → 3. serviço → 4. tool e prompt → 5. rota e fiação (`app.ts`/`index.ts`) → 6. front (lib → api → hook → componente → `TurnView`) → 7. E2E → 8. checkpoint.
